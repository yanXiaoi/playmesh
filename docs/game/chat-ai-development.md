# ChatAI 使用方法

ChatAI 是 Playmesh 面向普通对话 AI 的游戏开发方式。它适合 ChatGPT 一类只能进行
文字对话、不能直接访问本地项目或调用 Playmesh Developer API 的 AI。

Playmesh 会为当前项目生成完整提示词，其中包含游戏模式、页面角色、项目树、可用的
Developer Operation 基础指令、当前 SDK TypeScript 声明和已声明能力。项目文件内容
不会被一次性预载；ChatAI 会先生成读取指令，再根据执行结果继续工作。

## 开始前准备

1. 在 Playmesh App 设置中开启开发者模式。
2. 在 App 内或电脑浏览器中打开开发者工作区。
3. 创建游戏项目，或选择需要修改的已有项目。
4. 点击工作区顶部的“AI”，在公共分类中填写“自定义想法”。
5. 点击“获取项目提示词”，切换到“对话提示词”，复制完整文本或下载 TXT。

提示词后半部分包含当前 SDK 的完整类型声明，不要只复制开头的规则。修改项目模式、
显示模式或能力声明后，应重新生成提示词。

## 把提示词交给 ChatAI

将完整的对话提示词粘贴给 ChatAI，并紧接着说明本次目标。例如：

```text
请在不改变当前游戏模式和显示模式的前提下，为游戏增加三回合计分、
断线重连后的状态恢复，以及适合横屏触控的结算页面。
```

描述目标时尽量写清玩法、视觉、交互、必须保留的内容和验收条件。也可以先把长期想法
写入工作区的“自定义想法”，让它自动进入以后生成的项目提示词。

ChatAI 的可执行回复应是一个 JSON 指令对象或数组。如果 AI 另外给出操作说明，执行时
仍只复制 JSON 代码块，不要把 Markdown 围栏或说明文字一起复制。

## 在对话控制台执行

打开工作区“更多 → 对话控制台”，粘贴 JSON 并执行。典型的第一轮是按需读取文件：

```json
{
  "method": "GET",
  "path": "/dev/api/projects/com.example.game/file?path=app/index.html"
}
```

控制台会返回状态码、`requestId`、文件修订号和结构化响应体。将完整结果复制回原来的
ChatAI 对话，AI 才能根据真实源码生成下一轮修改指令。

完整往返流程通常是：

```text
ChatAI 生成读取指令
  -> 对话控制台执行
  -> 把结构化结果发回 ChatAI
  -> ChatAI 生成变更预览或应用指令
  -> 对话控制台执行
  -> 校验、运行并读取日志
  -> 把错误继续发回 ChatAI 修复
```

修改多个文件时，ChatAI 应优先使用 `file-changes/preview` 和
`file-changes/apply`。应用请求会校验预览返回的 `baseRevisions`，防止覆盖你或另一个
工作区在此期间完成的修改。不要手工改写 AI 返回的 revision。

## 校验和真实运行

文件修改完成不等于任务完成。继续要求 ChatAI：

1. 生成项目校验指令，并修复所有 `error` 诊断。
2. 生成启动或重启指令，在真实 Playmesh WebView 中加载游戏。
3. 读取当前运行状态和最近日志。
4. 根据日志、页面表现和你的试玩反馈继续修复。

涉及启动、重启或 WebView JavaScript 的操作需要 App 页面处于前台、设备已解锁且窗口
可交互。对话控制台会自动携带 ChatAI 通道标识，不需要把开发者 token 发送给
ChatAI。

## 审批与安全

操作目录中标记为 `dangerous=true` 的请求会暂停，并在工作区要求选择“允许一次”、
“对此游戏或项目允许”、“始终允许”或“拒绝”。只有在确认目标和变更范围后才批准。

虽然对话提示词不向 ChatAI 提供开发者 token，但你发送给外部 AI 的文件读取结果可能
包含游戏源码和资源信息。只向可信服务提供必要内容，不要发送账号凭证、内部 token、
私有文件或其他项目数据。

## 常见问题

- **控制台提示 JSON 无效**：只复制回复中的 JSON 对象或数组，不要复制说明文字和
  Markdown 代码围栏。
- **AI 臆造了接口或 SDK 方法**：重新生成并发送完整项目提示词，要求它只使用提示词
  中列出的 Operation 和 `.d.ts`。
- **文件 revision 冲突**：重新读取受影响文件，把新的响应交给 ChatAI，再重新生成
  预览和应用指令。
- **运行操作返回页面不可用**：让 App 回到前台、解锁设备并保持游戏页面可交互后重试。
- **改动结果不符合预期**：从工作区 Diff 或本地历史审阅和恢复，再把更明确的验收条件
  发给 ChatAI。

## 完成检查

- 项目校验没有 `error`。
- 游戏已在真实 WebView 中启动或重启，并完成实际试玩。
- 最近日志没有未处理异常。
- 游戏模式、显示模式、方向、玩家人数和 Authority 分层没有被意外改变。
- Diff 只包含本次目标需要的文件和清单变更。
