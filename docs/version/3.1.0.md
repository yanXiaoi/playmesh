## 修复内容

- 本地游戏与远程加入游戏统一接入菜单退出清理器。
- 收到 App 游戏菜单的退出请求时，先向当前 WebView 异步发起
  `about:blank` 导航，再立即调用原有退出回调。
- 空页面导航不被等待；无论成功、失败或尚未完成，都不会阻塞用户退出。
- Android 等 Flutter WebView 通过 `loadRequest` 发起导航；Windows WebView
  通过页面脚本执行 `window.location.replace('about:blank')`。
- 空页面加载失败只记录诊断日志，原有会话关闭、路由返回和资源释放流程保持执行。

## 用户功能

- 主页 AppBar 新增 GitHub 开源仓库图标，位于扫码与设置入口之间。
- 点击后使用系统外部浏览器打开 `https://github.com/yanXiaoi/playmesh`。
- 入口提供双语 Tooltip、键盘/TV 焦点和外部浏览器打开失败提示，并保持
  320dp 紧凑主页无溢出。
- 本地游戏库、在线游戏库、App 启动详情页和游戏内信息弹窗统一展示游戏标签。
- 所有标签完整保留在单行轨道中，有限空间可使用触摸、鼠标或触控板横向滑动。
- 保存和发布游戏时最多允许 5 个标签；Flutter 清单、开发者工作区与 Go Server
  使用相同上限。
- 开发者工作区在打开文本、图片或其他资源并刷新目录树后，会保留用户已经折叠的
  目录；切换项目时才重置展开状态。
- 游戏详情导出的 ZIP 使用 `名称-v版本.zip`；名称仍清理跨平台非法字符、尾部点号
  与空格并限制长度，Android 临时分享文件的租约和启动清理逻辑保持不变。

## 兼容性

- Game SDK 以向后兼容方式升级到 `3.1.0`，旧版游戏声明继续解析到当前实现。
- App Bridge SDK、Core、Catalog、Relay 与 Developer API 均未变化。
- 游戏无需新增生命周期监听或修改菜单调用方式。
- 系统返回键在 App SDK 接管前的原生退出行为保持不变；本次修复只收敛
  `app.game.exit` 菜单回调链路。

## 已知限制与人工验收

- 自动构建不能替代 Android 真机音频焦点、Windows WebView2 音频输出与生产签名
  证书的人工验收。
- `about:blank` 是退出前的尽力清理请求；用户退出不等待导航完成。

## 升级与回滚

- 无数据迁移、配置迁移或游戏包重建要求。
- 可直接覆盖安装 `3.0.0+23`。
- 回滚到 `3.0.0+23` 不需要清理本地数据库，但会恢复旧的 WebView 退出行为。
