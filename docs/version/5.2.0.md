## 用户变化

- Windows/Android 游戏中的文件下载自动打开系统保存窗口，可选择名称和保存位置。
- WebView 右上角新增原生下载图标；可查看全部、下载中、已完成列表及每个任务的进度、
  保存位置、来源、时间和错误详情。普通媒体播放不会仅因文件扩展名而触发下载。
  图标旁的关闭按钮可隐藏悬浮入口，下载继续；已有任务进度不打扰用户，新增下载或重开游戏
  后重新显示入口。
- 下载记录只存内存，以 `gameId` 区分；App 仍按单游戏实例流程运行。关闭游戏取消所有
  未完成任务并清理临时写入，已经保存的文件保留；重开相同游戏可以查看本进程历史，
  重新启动 App 后历史清空。
- Bucket 文件支持 HEAD 预检和 HTTP Range 分段读取，覆盖媒体播放常见的区间、末尾和
  多段请求。主 App 与独立 Runtime 行为一致。
- Windows App/Runtime 的 Profile、Release 构建禁用 WebView DevTools；Debug 保留
  开发调试能力。该行为按构建配置决定，不依赖启动 IDE。
- 修复 Windows Runtime 正式构建未使用当前版本参数的问题，EXE 文件/产品版本与
  Runtime `pubspec.yaml` 保持一致，并加入构建门禁。

## 实现与兼容边界

- HEAD 返回普通 GET 元数据且无正文。有效 Range 返回 206，多段使用 multipart/byteranges；
  全部越界返回 416 与总长度。If-Range 验证失败回退完整 200，既有头像 ETag 缓存优先级保留。
  读取按文件偏移流式进行；原有分享鉴权、路径校验及私有 JSON 隔离不变。
- Windows 保留 WebView2 原始下载，使用延迟的系统保存框；销毁时取消原生传输。
  Android HTTP 下载按目标读取 Cookie，网页 Blob/data 导出按有确认的分块保存，关闭后
  迟到的保存选择结果不会重新启动任务。
- Android 原生下载回调不含原 POST body 或自定义请求头；需要这些数据或一次性 URL 的
  下载不能保证重放成功，网页可先读取响应并以 Blob 导出。Blob 自动拦截限顶层文档。
  SAF 提供方可能先创建空目标文件，中断后不会擅自删除用户选择的目标。
- 没有持久化下载队列，不提供跨进程恢复或断点续传 UI。HTTP Range 支持与队列恢复是
  不同能力，不能将服务端分段读取理解为下载管理器已经提供自动续传。

## 实机验证、升级与回滚

本轮尚未独立完成 Windows/Android 安装后的系统保存框、覆盖写、实际媒体拖动和设备退出
中断验收；发布人的“正式发布”指令仅作为发行类型授权，不等同于宣称上述实机验收通过。
正式构建门禁检查签名、ABI、包结构、SDK 字节和哈希，不能替代真机行为验证。

升级不要求清空游戏数据。已导出的旧独立应用需要重新导出并安装，才能使用新 Runtime。
回滚应同时恢复 App、Runtime 固定资源及对应 update.json，不混用不同构建的文件与哈希；
两个 SDK 保持当前版本，游戏已保存文件不随回滚删除。
