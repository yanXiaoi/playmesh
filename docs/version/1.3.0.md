# Playmesh 1.3.0

发布日期：2026-07-18  
App 版本：`1.3.0+4`

## 升级原因

本版本首次接入 App 原生加速度计与陀螺仪，并把游戏能力声明从 `main.json` 中分离为可选的根目录 `capabilities.json`。这是向后兼容的新能力，App、Game SDK、App Bridge SDK、Developer API 与 Catalog API 均按 `MINOR` 升级。

## 用户变化

- 游戏声明设备能力后，主 SDK 会在 App 和普通浏览器每次加载游戏时展示能力确认。
- 弹窗只有“同意并进入”和“拒绝并退出”；确认结果不持久化，不写入 Authority 主机或游戏目录。
- 当前平台不支持的能力显示“本平台暂不支持”，但不会阻止用户同意后进入游戏；只有主动拒绝才退出。
- 合入此前 `NEXT` 中的返回页面动画性能优化：返回时取消整屏透明合成，仅保留 GPU 平移，并保留系统“减少动态效果”行为。

## 游戏包与开发者契约

- 游戏包根目录新增可选 `capabilities.json`，当前格式为 `{ "required": [能力ID] }`。
- 当前能力 ID 为 `sensor.accelerometer` 与 `sensor.gyroscope`；文件缺失或列表为空时不弹窗。
- 导入、导出、目录扫描、在线游戏源、开发者工作区、Schema、SDK Manifest、AI 提示词和校验器均识别该文件。
- 能力 ID 与提供方解耦，为后续 App/浏览器均可实现的摄像头、麦克风等通用能力保留统一模型。
- 新增统一能力注册表，集中维护 code、中文名、用途说明以及 App/HTML 适配状态；SDK 弹窗、校验和开发者界面均从该映射生成。
- 开发者工作区新增“项目设置”：`main.json` 除稳定 `id` 外均可可视化修改，支持标签输入；`capabilities.json` 可按统一注册表勾选编辑，全部取消时删除该可选文件。
- 游戏开发指南、开发者通道说明、内置 API 文档、纯聊天/Agent AI 提示词均同步能力声明、每次确认、降级规则、`onDevice` 回调和统一能力注册表；项目提示词会动态附带当前声明及完整注册表。

## SDK 与运行时

- 新增 `playmesh.app.DeviceType.accelerometer`、`gyroscope`。
- 新增 `playmesh.app.onDevice(type, fps, callback)`，`playmesh.app.device.onDevice` 为同一方法的别名；`fps` 为 `1` 至 `120` 的整数，返回取消订阅函数。
- 回调数据统一为 `{ type, x, y, z, timestamp, unit }`。加速度计单位为 `m/s^2`，陀螺仪单位为 `rad/s`。
- 每种传感器只建立一条原生采样流，采样频率取全部订阅者请求频率的最大值；App 内存保持最新样本，各订阅者按自己的 tick 频率收到回调。最后一个订阅取消、页面重载或退出时释放原生流。
- 能力弹窗由主 `playmesh.js` 统一创建，不由 Flutter 原生 UI 创建。拒绝时 SDK 在 App 中通过 App Bridge 请求退出；普通浏览器停止初始化并返回上一页。
- 当前原生传感器适配器支持 Android 与 iOS。局域网普通浏览器使用 HTTP，当前将两种运动传感器标为暂不支持并提供安全空实现。

## 兼容与升级注意

- 不需要设备能力的现有游戏无需新增 `capabilities.json`，运行行为不变。
- 声明传感器的游戏必须等待 `playmesh.ready`，并在 `getCapabilities()` 未返回对应能力时保持主流程可玩。
- 本版本不保存游戏能力授权，因此不存在授权数据迁移或清理步骤。
