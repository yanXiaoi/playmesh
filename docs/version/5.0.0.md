## 用户功能变化

- 创建房间、加入房间、邀请链接、扫码和分享/邀请界面入口及 URL 形态保持不变。
- 公网加入不再连接旧 TCP Relay。每个加入用户建立一个 PeerConnection；游戏资源与 Core
  连接的每条 TCP 流分别使用可靠、有序 DataChannel，避免把所有 HTTP/WebSocket 塞入单条
  全局通道产生队头阻塞。
- 直连不可用时由 Pion TURN 提供 relay candidate；没有 TCP fallback。连接失败会结束本次
  加入，用户需要从原入口重新进入。
- 主 App 与 Runtime 的分享/邀请房间成员列表显示 Core 判定的“局域网”“直连”或“中转”。
  多个加入用户拥有彼此独立的 PeerConnection、DataChannel 和状态，不会退化为单用户模型。

## SDK 与协议

- `playmesh.app.webrtc.getSignalingEndpoint(identifier)` 返回当前会话绑定、单次使用、30 秒
  过期的 WebSocket 信令 URL和 ICE servers。Core/Server 只鉴权、限流和转发 JSON；HTML
  自行使用原生 WebRTC 管理 SDP、trickle ICE、媒体轨、DataChannel、码率、摄像头切换、
  ICE restart 与显式关闭。
- 主 App 与 Runtime 复用既有可绑定 LAN IPv4 遍历结果传给 Go Core；Core 为该通用端点
  惰性提供 Authority 局域网 Pion STUN/TURN，短期凭据按会话、可信玩家和标识符隔离。
  存在公共会话时，端点在本地 ICE 后追加 Go Server 公网 ICE。
- 通用信令以 `sessionId + identifier + Core 已认证 playerId` 隔离，固定为 Authority 星形
  路由。加入端只能发给 Authority；Authority 给加入端发送时必须指定目标用户。
- 该 API 不新增或要求媒体源。既有 `playmesh.app.media` 保持独立，不能绕过信令票据、
  会话身份或路由限制。
- Core 内部 `Player.connectionMode` 只接受 `lan/direct/relay`，值由加入路径和 WebRTC
  selected candidate pair 生成；该字段只供宿主分享面板使用，不进入公开 Game SDK。
- 平台 PeerConnection 失效会关闭当前 web/core DataChannel 和本机 socket，不提供 ICE
  restart、自动换路或掉线 UI；Game SDK 仍通过 `playmesh.main.lifecycle.onChange()` 上报
  `closed/error`，并保留对原本本机 Session/Binary 端点的既有重试。该重试不能复活已关闭
  的 PeerConnection；需要换路时仍由玩家从既有入口重新加入。
- Game SDK 仍只接受请求版本 `4.1.0`；App Bridge SDK
  接受 `3.2.0`、`3.3.0`、`3.4.0`、`3.5.0` 并解析到 `3.5.0` bundle。
- 新的 `playmesh.app.ui.onSystemMenuRequest()` 统一在 Android 系统返回、Windows exe 返回键和普通浏览器
  悬浮菜单按钮触发后、默认效果发生前执行；再按 `EXIT / NEXT / STOP` 决定退出、继续该入口
  原有的菜单流程或停止，不再由浏览器悬浮按钮绕过游戏回调。原 `onBack()` 已标记废弃并作为
  相同行为的兼容别名保留。

## 部署变化

- Go Server 只保留 Catalog、WebRTC 信令、鉴权、TTL、限流和 Pion TURN/STUN；旧 TCP
  Relay listener、升级协议和字节复制链已删除。
- TURN 生产部署需要显式配置独立共享密钥、可公网到达的 IPv4、3478 TCP/UDP 和受控 UDP
  relay 端口范围。Go Server 动态签发临时 TURN REST credential，游戏包不保存 TURN 长期
  密钥。
- Relay 3 与 Relay 4 不支持混部兼容。App、Runtime、Go Core 与 Go Server 必须作为同一
  组升级或回滚，旧邀请按 TTL 自然失效。

## 升级与回滚

- 升级必须同时部署 Relay 4 Go Server、Go Core、App/Runtime 和 SDK 生成物，不能只替换
  Server 或只给 Core 增加 WebRTC。
- 回滚时整组回到 App `4.5.0+33`、Runtime `1.0.2+8`、Go Core `0.5.0`、Core `1.3.0`、
  Game SDK `4.1.0`、App Bridge SDK `3.3.0`、Relay `3.0.0`；不要尝试在 Relay 3/4 间
  自动迁移正在进行的连接。
- 本次不迁移用户身份、游戏包或 Bucket 数据；回滚不需要清理这些持久数据。短期信令票据、
  ICE credential 和旧邀请均不可迁移，应让其过期后重新创建房间。
