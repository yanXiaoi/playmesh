# Playmesh 1.1.0 更新日志

## 发布信息

- 发布日期：2026-07-18
- App：`1.0.0+1` → `1.1.0+2`
- Go Core：`0.1.0` → `0.2.0`
- Game SDK：`1.1.0` → `1.2.0`
- App Bridge SDK：`1.0.0`
- Developer API / OpenAPI：`1.0.0`
- Core 协议：`1.0.0`
- 历史归档：本版本对应最后一个阶段归档 `docs/status/phase-06-complete.md`；后续只维护版本日志

## 升级原因

本版本加入了兼容的移动运行、跨 App 加入、玩家连接事件和会话结束能力，因此 App、Core 与 Game SDK 分别升级次版本。Developer API、App Bridge SDK 和 Core 协议没有不兼容变化，保持原版本。

## 用户可见变化

- 扫描主机二维码即可加入对局，无需先在加入设备安装游戏；根据主机模式直接进入游戏或控制器。
- 游戏、控制器和外部 HTML 的全屏成为可选操作。无法全屏时只显示提示，不影响加载和游玩，右上角悬浮工具可按需进入或退出全屏。
- Android 游戏包导入成功后不再误报失败；导出通过系统保存或分享面板完成。
- Android 可从其他应用接收打开/分享的压缩包和 HTML。压缩包进入 Playmesh 包导入，单个 HTML 在无 SDK 权限的独立 WebView 中运行。
- 移动端开发工作区改进顶部按钮、二级菜单和弹层边界；项目选择支持搜索，文档点击后跳转编辑区。
- 页面与开发者模式切换减少阻塞和二次渲染感。

## 开发者与 SDK 变化

- `playmesh.js` 是 Authority 主机运行时，负责日志、会话、联机、状态同步和游戏存储。
- `playmesh-app.js` 只由 App WebView 自动注入，负责当前 App 持久身份和已授权本机能力；普通浏览器只获得 `playmesh.app` 安全空实现。
- App 玩家自动使用自身 `u_...` ID 和昵称；浏览器将随机 `p_...` ID 与昵称持久化到当前来源的 `localStorage`，刷新后复用。
- 同一玩家 ID 同时只允许一个在线 WebSocket；旧连接离线后才允许同 ID 重连。
- Game SDK `1.2.0` 新增 `playmesh.session.onPlayerJoin`、`onPlayerLeave`、`onPlayerReconnect` 和 `finish()`。
- Core 只在 `running` 或 `paused` 保留离线成员；`lobby` 离线释放成员，`stopped`、`finish()`、重置和重新开始清理旧局离线成员。
- AI 提示词、SDK Manifest、SDK Schema、默认模板和编辑器补全已同步双 SDK、持久身份、重连事件、会话结束与 Game SDK `1.2.0`。

## 版本与文档规则

- 后续所有更改都必须按需升级受影响组件版本，遵循 `docs/06-engineering-standards.md` 的当前语义版本与 Flutter 构建号定义。
- 第六阶段之后不再建立阶段文档；每个发布版本在 `docs/version/` 保存详细日志，并在 App 设置页同步显示简略日志。
- 游戏项目的 `main.json.version` 和 `sdkVersion` 由平台发布流程管理；AI 工作区保持只读，不提供绕过接口。

## 验证与限制

自动验证见 `docs/verification/phase-06-complete-2026-07-18.md`。未执行 Android、iOS、Windows、macOS 或 Linux 平台构建；扫码、系统文件入口、系统分享面板、WebView 全屏和不同尺寸工作区仍需在目标平台手工确认。

## 升级注意事项

- 默认项目模板已要求 Game SDK `1.2.0`。开发期只维护当前实现，不恢复旧 SDK 入口或双写兼容层。
- 浏览器玩家凭证和游戏 Bucket 不写入 `localStorage`；只有 SDK 管理的玩家 ID 与昵称可以持久化。
- `session.finish()` 表示本局玩法真正结束，不用于页面隐藏、暂停或临时掉线。
