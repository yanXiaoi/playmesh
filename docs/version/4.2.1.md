## 用户变化

- 源代码工作区的安装包导出改为紧凑的平台卡片轨道；Android ARM64、Android x86_64
  与 Windows x64 可左右滑动选择，角标直接显示“已安装”“未安装”或“可更新”。
- 移除底包版本、“已安装底包”“可下载底包”等重复诊断行。只有本地底包 SHA-256 与
  Runtime 清单 SHA-256 不一致时才显示“可更新”，版本字符串不参与判断。
- 移动端中转服务器菜单在对话框文档流内展开，不再自动聚焦搜索框或弹出软键盘；桌面端
  继续保留手动搜索。Android 与 Windows 使用同一份工作区 HTML、CSS 和 JavaScript。
- GDevelop 主页把“关于此编辑器”恢复到与“创建”相同的侧栏列，并将桌面、移动端主页动作
  统一缩短为 2–3 个汉字，减少窄屏横向挤压。
- 源代码工作区和 GDevelop WebView 刷新不再重放含一次性凭据的初始 URL；共享 Dart
  协调器会去除 query/fragment 后加载稳定 URL，从而重新取得有效 capability。

## 开发者与协议变化

- `package_exports.options` 的每个 Runtime 目标新增布尔字段 `updateAvailable`。该字段只有在
  目标已经安装、存在可用下载线路且本地文件摘要与远端目标摘要不一致时为 `true`；文件读取
  失败保守返回 `false`。既有字段继续保留，旧客户端可忽略新增字段。
- Developer API / OpenAPI 因兼容新增可选响应字段升级到 `4.4.0`；操作路径、请求正文和
  Operation ID 均未变化。
- 工作区 UI 只消费上述摘要结果，不在 JavaScript 中复制文件哈希或版本比较逻辑。
- Windows WebView2 与 Android Flutter WebView 的刷新入口继续由共享
  `DeveloperWorkspacePage` 协调；平台适配器仅负责加载传入 URI。

## 已知边界与回滚

- 本轮完成自动化与正式构建验证；Android 软键盘在不同输入法、窗口缩放和横屏组合下仍应
  继续补充实机视觉验收。自定义地址输入按设计会主动打开键盘。

  `resources/app` 两个固定镜像及本版 GDevelop revision，避免代码、更新清单和二进制不一致。
