## 在线游戏库

- 首页加载下一页时保留已展示游戏，只在“加载更多”按钮内显示进度。失败时保留已有结果并
  重试同一页，不再把整个来源退回首次加载或错误状态；不同来源继续独立维护页码或 cursor。
- 首页和聚合搜索结果均可点击游戏卡片打开详情。详情复用本地游戏的信息结构，展示发布者、
  来源、版本、大小、人数、屏幕方向、模式和 SDK 信息，并继续调用既有版本/来源选择与下载链。
- 首页保留快捷下载按钮，搜索结果新增独立下载按钮；键盘、电视焦点和窄屏布局由组件测试覆盖。

## App 本地存储与 GDevelop

- 同版本 App Bridge SDK `3.3.0` 的内置实现为 `playmesh.app.storage` 补充
  `getDataSync/setDataSync`。App WebView 通过仅绑定回环地址、带随机 capability 的同步
  HTTP 通道访问现有 `AppLocalBucketStore`，数据仍按游戏隔离且只归当前设备所有。
- 同步逻辑桶允许 1～4096 个 UTF-8 字节的 GDevelop storage file 名称；磁盘只使用名称的
  SHA-256 路径并在内容中保存、复核原逻辑名，避免路径逃逸或哈希映射混淆。普通异步 Bucket
  的既有名称、key、10 MiB 上限和 Promise 语义不变。
- GDevelop `storagetools` 从 Authority 的 `playmesh.main.storage` 迁移到当前设备的
  `playmesh.app.storage`。上游 GDevelop 版本保持 `5.6.276`，Playmesh revision 升到 `21`，
  重打包 ZIP 的大小与 SHA-256 同步写入 `resources/GDevelop/update.json`。
- Game SDK `4.1.0` 与 App Bridge SDK `3.3.0` 均不升级；生成器、Manifest、Schema、类型声明、
  Runtime SDK 快照和 GDevelop 扩展保持同一内容来源。

## Runtime 与发布资源

## 已知边界与回滚

- 自动化覆盖分页状态、焦点与详情下载链，但实际 Catalog 服务器的多来源 cursor、弱网重试、
  大图标和大清单仍需真实网络交互验收。
- 同步存储会短暂阻塞 WebView JavaScript 线程，只应用于 GDevelop 要求的同步存储语义；普通
  游戏数据仍优先使用异步 Bucket。回环服务不监听 LAN，capability 不写日志或持久化。
- 本轮发布不等于 SDK 升级。回滚 App 时应同时回滚 App 固定镜像、更新清单、Runtime 三个
  固定底包及清单和 GDevelop ZIP 及清单，避免同名资源与摘要不一致。
