## Core 与状态同步

- Go Core 移除主 Session WebSocket 每连接每秒 30 条消息的应用层计数限制；消息大小、认证、
  权限和出站队列等既有边界继续生效。“无限制”只指不再按消息条数主动关闭连接。
- `playmesh.main.game.startAuthority({tickRate})` 和
  `playmesh.main.sync.submitState(..., {rateHz})` 的公开上限从 20 Hz 提升到 60 Hz；生成声明、
  Manifest、开发提示和 GDevelop 扩展同步使用 60 Hz。

## 游戏菜单与返回

- 进入与退出全屏合并成一个状态按钮。分享/邀请之后增加简洁的“加入游戏”入口，弹窗只保留
  当前游戏局域网房间、扫码和邀请链接输入，不放说明段落。
- 加入入口与分享/邀请共用 Authority 主机可见性，并额外要求 App 原生 Bridge；加入端
  WebView 和普通浏览器均不显示或触发。
- `playmesh.app.ui.onBack(callback)` 的 boolean 返回方案仅作为未生效草案出现，没有进入正式
  SDK 契约；当前有效定义以 SDK 开发规范和 `docs/game/sdk-v1.md` 为准。

## 连接生命周期

- 修复 Windows WebView2 和移动端只产生内部 `transport.status`、没有转发到公开生命周期的
  问题。浏览器、Windows 和移动端现在统一通过 `playmesh.main.lifecycle.onChange()` 接收主
  连接的 `closed/error`，游戏无需感知底层运行环境。

## 已知边界与回滚

- 自动化和正式构建不能替代 Android 返回手势、真实扫码、两台设备局域网发现/加入以及
  Windows WebView2 断网行为的实机验收。
- 回滚必须同步回滚 App 与 Runtime 固定镜像、两份更新清单、SDK 生成物、Core、GDevelop
  扩展和本版日志，不能只回滚界面或 App 版本常量。
