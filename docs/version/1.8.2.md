## 修复内容

- 单屏多人权威显示端固定加载 `entries.game`，只取得 `capabilities.json.required`。
- 单屏多人加入端固定加载 `entries.controller`，只取得 `controllerRequired`。
- 页面角色判定同时用于入口、方向和能力，避免三条链路分别推断后出现漂移。
- Game SDK 在 App WebView 中以 App Bridge 的 `getDeclared()` 作为当前页面声明的权威来源；空数组是有效声明，不再回退到通用字段或另一角色的能力。
- 普通多人多屏的加入端仍使用主画面入口和 `required`，不会误判为单屏控制器。

## 兼容性

- `capabilities.json` 结构、Game SDK 公开 API、App Bridge API、Core 协议和 Developer API 均未改变。
- 已发布游戏无需修改。原本仅在 `controllerRequired` 声明能力的单屏多人游戏，显示端不再出现能力确认，控制器行为保持不变。

## 验证

- SDK Node 契约测试覆盖“通用字段含控制器能力、当前 App 页面声明为空”时不弹能力确认。
- Flutter 模型测试覆盖 `required: []` 与非空 `controllerRequired` 的严格角色分流。
- Flutter Widget 测试覆盖单屏多人权威显示端加载主入口且注入空能力列表。
- Android 与 Windows 构建结果记录在 `docs/verification/playmesh-1.8.2-role-capability-build-2026-07-24.md`。
