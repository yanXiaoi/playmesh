# Playmesh 5.1.0 更新日志

- 日期：2026-09-01
- App：`5.1.0+37`
- Runtime：`2.1.0+12`
- 状态：预发布候选；源码自动化、GDevelop WebIDE、Runtime 三端固定底包和主 App
  Android/Windows 正式包已完成，尚未完成真机、跨设备、长时在线与公网 TURN 手工验收
- 最新正式发行：`4.5.0+33`

## 升级原因

本版把项目身份、游戏清单、数据库、流式 RPC、WebRTC、邀请加入、局域网发现与系统菜单等
近期兼容新增集中形成可分发候选。发行前审计还发现 GDevelop 项目重建在把旧项目迁移到合法
Android applicationId 时只重写 `gameId`，没有同步迁移 `identityPolicy`，导致新目录生成后
无法重新打开；本版补齐该元数据迁移并增加完整生命周期回归。

本次同时按项目发布规范重新生成 SDK、构建 GDevelop WebIDE、Runtime 固定底包和主 App，
并以 SHA-256 反查主仓、Runtime 清单及 GDevelop 扩展消费面。SDK 版本与机器契约按兼容性
规则升级；没有以打包成功代替尚未执行的平台手工验收。

## 用户与开发者变化

- 浏览器多人入口在没有本地昵称时自动生成并保存“浏览器”加 4 位随机小写字母或数字；
  已有昵称、手动改名、App 身份、玩家 ID 和重连语义保持不变。
- App SDK“加入游戏”面板持续订阅主 App 与 Runtime 共用的局域网发现 lease，房间新增、
  更新、goodbye 或 TTL 失效会立即反映，不再只显示首次快照。
- 游戏清单的主画面与单屏多人控制器方向新增 `system`，新模板、普通网页导入、CLI/Cocos、
  GDevelop 与宿主默认值统一；已有项目的显式横屏或竖屏不迁移。
- Runtime 接受随包兼容基线至最高 Bundle 的严格语义版本闭区间：Game SDK
  `4.1.0`～`4.3.0`、App SDK `3.2.0`～`3.5.0`。格式错误、低于基线或高于随包最高版本
  继续拒绝。
- Game SDK `4.3.0` 新增 `rpc.requestStream`、`rpc.onStreamRequest` 与数据库能力。
  大字节流使用 Core HTTP 数据面、32 KiB 有界 pipe、背压和兼容普通浏览器/Android WebView
  的 `chunked-v1` 会话；单流上限 512 MiB，并保留超时、并发、身份和 Authority 边界。
- App SDK 保留 `ui.onSystemMenuRequest()`，统一 Android 系统返回、Windows 返回键与浏览器
  菜单按钮；`ui.onBack()` 作为兼容别名保留。
- App 与 Runtime 的邀请、扫码、LAN/Relay 会话移交、房间成员刷新、Bucket 同步和 WebRTC
  信令实现保持同一宿主合同。完整细项与边界保留在 `docs/version/NEXT.md`。
- GDevelop 项目重建把合法的新项目 ID 同步写入 Android applicationId 身份策略；锁定阶段
  不提前创建目标目录，提交后才切换身份并保留可恢复日志。

## 已知限制与升级注意

- 尚未安装 Android 真机、运行 Windows 真实窗口，也未执行两台设备跨网、超过 6 小时在线
  或公网 TURN 手工验收；自动化和包结构检查不能覆盖相机权限、运营网络、NAT、驱动与
  WebView2 现场行为。
- `mobile_scanner` 与 `speech_to_text` 当前仍触发 Flutter Built-in Kotlin 未来兼容警告；
  本版可以构建，但升级到未来强制版本前必须先升级或修复插件。
- Gitee 发布流程按项目脚本只镜像源码、`resources/` 固定资源和发布条目，不上传主 App
  二进制附件；主 App APK/ZIP 以 GitHub Release 为二进制发布源。
- 回滚时必须同时恢复 App/Runtime 源码、GDevelop ZIP、Runtime 三个固定底包及两份
  `update.json`，避免下载清单与真实文件哈希不一致。数据库与清单新增字段保持兼容，
  本版不要求主动清理用户数据。
