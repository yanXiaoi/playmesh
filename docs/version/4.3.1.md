## 语音能力与完整自检

- `media.microphone@1.1.0` 仍先执行真实语音引擎初始化。只有初始化失败后才调用平台诊断，
  不再把所有失败统一提示为麦克风授权问题。
- Android 主 App 与 Runtime 诊断系统 `RecognitionService` 和设备内识别服务是否存在；
  Windows 主 App 与 Runtime 通过 SAPI 区分识别器、默认录音输入、识别上下文、听写语法和
  语言资源失败。Windows 原生目标显式使用 UTF-8 编译，诊断文案不会受系统代码页破坏。
- 能力自检完整执行 `create({})`、实际初始化和 `dispose()`，不存在 bootstrap 预检捷径。
  平台诊断仅细分真实失败原因，并返回稳定 `errorCode`。
- `CapabilityOperationException` 的错误码会经过 Developer 能力测试、App Bridge 命令错误、
  `app.capability.error` 异步事件和 App SDK `Error.code` 保留。Game SDK `4.1.0` 与 App SDK
  `3.3.0` 均不升版，Runtime 和 GDevelop 扩展已按 SDK 开发文档同步。

## 检查更新界面

- 设置页入口和弹窗标题统一为“检查更新”，加载、来源和浏览器反馈文案保持简短。
- 新版本说明不再占用主弹窗空间，改为点击“查看版本说明”后在独立弹窗展示。
- 下载线路卡片在窄屏下固定单行：线路名称超长时省略，状态直接显示 `36ms` 等毫秒值，
  打开操作使用图标。360 像素宽组件测试覆盖超长线路名称与溢出检查。

## Runtime 与发布资源

- Runtime `1.0.2+5` 串行重建 Android x86_64、Android arm64-v8a 和 Windows x64 三个底包，
  并同步 `resources/runtime/update.json` 的版本和平台级 SHA-256。
- App `4.3.1+31` 正式构建覆盖两个 Git LFS 固定镜像；Android APK 使用仓库正式签名并通过
  APK Signature Scheme v2 验证，Windows portable ZIP 通过 28 项发布资源复核。
- 旧的 `assets/app/app_update.json` 已移除。运行时只从 `assets/app/App.json` 指向的远端
  `resources/app/update.json` 检查更新，不存在内置清单回退。

## 已知边界与回滚

- 自动化和正式构建能确认完整初始化调用、错误码契约及原生桥可编译，但不能替代系统语音
  服务和真实录音设备验收。审计时连接的 Android 15 设备没有可用
  `android.speech.RecognitionService`；本机 Windows SAPI 识别器存在，但默认语音录音输入
  不可用。权限按本次范围未处理，也不能据此声称语音识别已在这些设备上成功完成。
- 回滚必须同时回滚 App/Runtime 版本、两份更新清单、五个固定镜像、两端原生宿主、SDK
  生成物、GDevelop 扩展及本版日志，不能只回滚 Flutter 界面。
