# Playmesh 4.2.0 版本日志

## 发布信息

- 发布日期：2026-08-21
- App：`4.2.0+28`
- Git 标签：`v4.2.0-build28`
- 发布平台：Android universal、Windows x64 portable
- 主分支固定镜像：`resources/app/playmesh.apk`、`resources/app/playmesh.zip`

`3.3.0` 清单请求均解析到兼容的 `3.3.0` bundle。

## 用户变化

- 设置页不再承载开发者模式。首页新增“制作游戏”，在同一 Developer Gateway 会话下分别
  展示源代码开发与基于开源 GDevelop 的可视化开发入口。
- 加入页可显示同一局域网内由房主显式公开的附近对局，展示游戏、主机、真实来源 IP 和
  人数信息，并与扫码、手工链接共用同一邀请预检和加入流程。
- 游戏分享由一个协调器统一管理 LAN、Relay、二维码、房间状态、公开租约和退出清理；
  没有可用 LAN 地址时不再返回 `127.0.0.1` 伪分享地址。
- 设置页“关于 Playmesh”新增手动检查更新，可并发读取 `App.json` 中的 App 渠道，选择
  最高有效语义版本并按当前平台显示下载线路和延迟。App 只交给系统浏览器打开下载地址，
  不在应用内下载、校验或安装主应用更新。
- 源代码工作区把原“发布”改为“导出”，统一提供“导出源码”“上传到发布源”和
  “安装包导出”；游戏详情不再重复提供游戏包导出。

## 附近对局与 App Bridge SDK 3.3.0

- 自动发现使用唯一自定义 IPv4 UDP multicast `239.255.80.77:53584`，wire v1、1 秒公告、
  4 秒 TTL、单包最多 1200 字节。启动游戏和开发预览默认不公开；打开分享面板或本机房主
  调用无参数 `playmesh.app.lan.setPublished()` 后才公开，退出游戏时停止并发送
  best-effort goodbye。
- Android、Windows、macOS、Linux 覆盖有效物理 IPv4 网卡和支持组播的虚拟网卡，按数据报
  source IP 识别主机并隔离部分接口失败。iOS 自动发现/发布明确为 `unsupported`，扫码、
  手工邀请和分享链接继续可用。
- `playmesh.app.lan` 提供需要真实用户操作的发现、链接加入和扫码加入；当前本机
  Authority/standalone host 的 App WebView 可无副作用读取与分享面板相同的完整链接和
  PNG Data URL。链接、Token 和 PNG 不写入日志、磁盘、分析或崩溃详情。
- `playmesh.app.ui.disableSystemMenuTriggers()` 可幂等解绑当前文档默认的
  Escape/Menu/Back 菜单触发；显式菜单方法仍可用，文档刷新后恢复默认绑定。
- `playmesh.app.ui.onGameMenuOpen()` 与 `onGameMenuClose()` 提供真实菜单状态切换事件，
  单个游戏回调失败不阻塞菜单和其他监听器。
- Go Core Session 的 `MaxPlayers` 硬上限由 16 提高为 32；GDevelop Multiplayer 的独立
  8 人编号与 readiness 协议不随此项扩容。

## 制作游戏、GDevelop 与本地 AI

- GDevelop 当前工程、历史 revision 与恢复事务完整保存官方 folder-project 多文件树和
  图片、音频、视频、字体、3D 等 PlaymeshLocal 资源。每项目 CAS 以 SHA-256 去重，
  current/history 分别 pin，只有零引用 Blob 才可回收。
- WebIDE 保存前批量检查资源 presence，只上传 CAS 缺失内容；每 60 秒自动保存与预览前保存
  复用同一去重入口。历史默认保留 50 revision、256 MiB unique CAS、32 MiB project
  files、64 MiB 单资源，桌面配置可提高到 100 revision、1 GiB 与 128 MiB。
- managed project 身份、列表、canonical current 与历史证据由 App Gateway 持有；项目
  allocation、rekey、另存、复制和恢复使用原子事务、幂等查询和只向前恢复。
- 本地 AI 开发流升级为 v4：Chat/Agent 共用锁定 GDevelop 5.6.276 的 50-tool 合约、统一危险
  操作审批、单 writer lease、editor-session 上下文和明确的超时/取消边界。AI 只调用当前
  WebIDE 活动工程的官方 EditorFunctions，不替用户保存工程或创建历史 revision。
- Tool Contract 升级为 `4.0.0`，17 个直传工具使用官方当前函数名与完整参数；
  `add_scene_events` 使用固定 `GDevelopEventPayload 1.0.0` 信封。
- 恢复离线锁定的 Piskel、Jfxr、Yarn 外部编辑器，并由 PlaymeshLocal 接管资源保存；移除
  分析、账号、公共发布和远程词典等联网服务。本地 AI 工具复用同一套编辑器实现。
- Playmesh 内置扩展和目录源进入 WebIDE；固定源码策略、官方 libGD 配对和 clean-replay
  校验共同阻断上游实现或字段漂移。

## 导出、安装包与更新资源

- 源码导出复用 `GET /dev/api/projects/{projectId}/package`。普通浏览器执行标准下载；App
  WebView 由原生宿主携带当前 Developer Token 流式保存。浏览器与原生建议文件名统一为
  `{游戏名称}-v{版本}.zip`。
- 上传到发布源继续执行完整校验、多源并行上传、SSE 状态、失败源重试和版本冲突处理。
- 安装包导出使用 `package_exports.options/create/download/release`，选择 Android ARM64、
  Android x86_64 或 Windows x64，并可配置一个内置中转服务器。主 App 不打包 Runtime
  底包；服务按 `App.json -> Runtime update.json -> 目标下载线路` 下载、SHA-256 校验、
  固定目录缓存并支持强制刷新。
- Android 导出向 Runtime 底包注入游戏、加密、签名并产出 APK；Windows 导出重写资源后
  产出 portable ZIP。源码包与安装包共用浏览器下载/App 原生保存和清理函数，并提供 Runtime
  下载、原生导出与完成/失败进度。
- `POST /dev/api/packages/import` 改为请求流直接写入临时 ZIP；长度超限、30 秒无数据、空流
  和中途异常均返回稳定错误并清理部分文件。同 ID 更新继续原子替换用户包内容并保留平台
  拥有的 `data/`、`cache/` 与 `.playmesh/`。
- App 正式构建除生成带版本号的 Release 附件外，还覆盖并通过 Git LFS 提交
  `resources/app/playmesh.apk` 与 `resources/app/playmesh.zip`，供 `app_update.json` 的
  主分支镜像地址读取。APK 超过 GitHub 普通 Git 的单文件上限，因此不能作为普通 Git Blob
  提交；LFS 指针和对应二进制对象共同构成受版本控制的固定镜像。GitHub 保存对应 LFS
  对象；Gitee 免费仓库不支持 LFS，因此只同步 Git 提交与指针，不作为这两个文件的下载源。

## Game SDK、存储与 Developer API

- Game SDK `4.1.0` 为 `game.submitAction` 与 `authority.onService` 兼容增加 namespace
  路由；不传 options 的旧调用继续使用稳定默认路由和原 wire 形状。
- JSON Bucket 保留 `getData/setData/removeData/clearData/upload` 公共签名与 Promise 语义，
  新增锁定 Runtime 使用的 `getDataSync/setDataSync`。异步与同步 JSON 统一通过同源
  HTTP GET/PUT/DELETE、SHA-256、requestId 幂等与 revision/CAS；binary upload 继续使用
  独立 POST 与 `data/data`。
- Developer API / OpenAPI `4.3.0` 由同一 Operation Definition 注册表生成路由、OpenAPI、
  操作目录和 AI 指令；新增安装包导出、GDevelop 历史/AI/allocation/rekey 与临时开发资源
  会话契约。
- Developer CLI `playmesh-cli convert` 可把标准 `main.json + app/` 包原子转换为 JavaScript
  CLI 2.0 工程，安装当前 SDK、迁移可选能力与图标并拒绝覆盖已有脚手架。

## 已知边界与人工验收

- Android、Windows、macOS、Linux 的 LAN 跨设备发布、发现、更新/丢失、权限拒绝、网络
  切换、物理/虚拟网卡组合和实际加入仍待实机验收。4.2.0 正式发布不代表这些实机项已经
  完成；iOS 只承诺稳定 `unsupported` 和保留扫码、手工邀请、分享链接入口。
- AP 隔离、VLAN、防火墙、禁用组播或 VPN/虚拟网卡策略可能阻断发现，不能把局域网能力
  描述为无条件可达。
- App 内手动更新只展示并打开外部下载地址，不负责主应用安装包校验和安装；正式制品完整性
  以 Release 附件旁的 `SHA256SUMS.txt` 为准。
- Android/iOS/Windows 的源码包与安装包实际系统保存/分享界面仍应按平台补充人工验收。

## 升级、回滚与数据清理

- 从 4.1.0 升级不需要迁移 Catalog、Relay、Go Core 会话数据库或普通游戏包数据。
- 现有游戏工程应由工作区或 CLI 同步清单中的 Game SDK/App Bridge SDK 版本，不手工维护
  与实际生成 SDK 不一致的字段。
- GDevelop v3 current/history、项目 allocation 和 AI v4 editor session 不向旧宿主提供
  回退读取。回滚 App 前应先导出需要保留的项目源码；旧版不会理解新版侧车状态。
- 回滚主应用时不得继续发布 4.2.0 的固定镜像；`resources/app/playmesh.apk`、
  `resources/app/playmesh.zip` 与 `assets/app/app_update.json` 必须作为同一发行单元回滚。
