## SDK 唯一源与自动组装

- Game SDK 与 App Bridge SDK 的唯一手写源迁移到
  `lib/core/game_sdk/features/` 下的 Dart feature。
- 每个 feature 在同一个 Dart 文件中维护 TypeScript、类型声明片段和对应宿主执行器；
  `sdk_feature_registry.dart` 是唯一注册与分发位置。
- App 运行、游戏资源网关、分享网关、本地 App SDK 服务、Developer Gateway、SDK
  下载和 AI 声明都从注册表即时组装 SDK，不读取打包静态文件。
- 日常开发只需重新运行 App；Android、Windows 等正式构建入口会自动执行生成器，
  更新可审阅的 TS、JS、`.d.ts`、SDK Manifest、Schema、默认模板和提示词。
- 测试扫描所有 SDK 消费入口，禁止恢复 `rootBundle`、文件系统或测试注入脚本旁路。

## 执行器版本兼容

- 游戏清单的 `sdkVersion/appSdkVersion` 先选择已注册兼容发行版；未知或格式错误版本
  直接拒绝，不会静默使用最新版。
- 每个 Dart 命令执行器通过 `supportedVersions` 自行声明适用 bundle。
- 调用契约未改变的执行器使用 `SdkVersionRange.last` 开放上界，会自动支持后续已注册
  最新版，不需要在每次 SDK 升级时逐个改版本。
- 命令名不要求全局唯一；多个执行器可以为同一命令提供不重叠的历史实现。注册器与
  生成器强制拒绝“同一命令 + 同一版本”命中两个执行器。
- 只有参数、消息结构、返回值、事件或错误语义发生不兼容变化时，才封口旧执行器范围，
  并可在 `features/game/v3/` 或 `features/app/v3/` 注册新实现。未变化的 feature
  保持原位并继续使用 `last`。

## 会话业务边界

- `playmesh.session.start()` 与 `finish()` 是受控 Core 会话状态请求，不负责决定玩法
  是否可以开始、胜负或本局是否结束。
- 准备、倒计时、开始、结算和再开一局条件由游戏 Authority 判断。单屏多人公共显示端
  不提供玩家可点击的开始按钮。
- `finish()` 继续由 Authority 调用，用于把基础会话切换为 `stopped` 并回收离线席位；
  在线玩家可以保留到下一局。

## 兼容性

- Game SDK 与 App Bridge SDK 的公开方法签名未变化。
- 当前 Game SDK 发行范围为 `1.0.0-2.2.2`，App Bridge SDK 为
  `1.0.0-2.1.1`；已安装旧游戏继续按清单版本选择兼容 bundle。
- `/playmesh/sdk/v1/` 保持稳定 URL；路径中的 `v1` 不是语义版本。
- 回滚 App 时一并回滚 Dart feature 注册表与该构建生成的 SDK 契约产物，不能只替换
  静态 JS。
