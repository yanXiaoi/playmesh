## 用户与开发者变化

- 仓库根 `README.md` 成为完整英文默认入口，原中文内容完整保留为
  `README.zh-CN.md`，两份文档顶部互链。`docs/` 继续保持中文权威资料，不建立无法同步
  的英文镜像。
- ChatAI 与 AgentAI 提示词随 Developer Workspace 当前 App locale 生成。英文版本完整
  覆盖公共对话规则、Agent 执行规则、自定义想法、单机、多人、普通多人多屏与单屏多人。
- 提示词模板按
  `assets/playmesh-library/public/developer/prompts/{locale}/` 分目录维护；同一
  `prompts/manifest.json` 为全局语言清单中每个启用 locale 声明全部模板文件。
- 模板名称、分类、动态项目段落、操作目录标题与能力描述不在提示词目录维护第二份翻译，
  统一读取全局 `app.json`。默认 locale、启用语言与 fallback 统一读取
  `assets/playmesh-localization/manifest.json`。
- 工作区打开提示词面板、预览或下载项目提示词时自动携带当前 locale。语言切换后，未修改
  的模板面板会重新读取对应语言；存在未保存内容时仍绑定原 locale，避免把一种语言误存到
  另一种语言。
- 每个 locale 的用户模板覆盖独立存储。默认 locale 继续兼容既有覆盖路径，其他 locale
  使用自己的子目录；保存或恢复一个 locale 不影响其他语言。

## Developer API 4.1.0

以下接口兼容新增可选 BCP 47 `locale` 查询参数：

- `GET /dev/api/ai-prompt-templates`
- `PUT /dev/api/ai-prompt-templates/{templateId}`
- `DELETE /dev/api/ai-prompt-templates/{templateId}`
- `GET /dev/api/projects/{projectId}/chat-prompt.txt`
- `GET /dev/api/projects/{projectId}/agent-prompt.txt`

解析先按完整 locale ID 匹配，再按语言子标签匹配全局已启用 locale，仍未命中时使用全局
`defaultLocale`。模板响应新增解析后的 `locale`；项目提示词下载文件名包含解析后的 locale。
运行代码不包含 `zh-CN`、`en-US` 或其他特定语言分支。新增语言只需补齐统一语言声明、
对应 `app.json`、提示词语言目录、清单映射和 Flutter 资产目录。

非默认 locale 的生成提示词不会携带仅以默认语言编写的 Operation 描述或 SDK JSDoc，
但保留语言无关的真实 method、URL、权限、风险、参数、请求示例、SDK 类型签名与补全标记；
能力名称和说明按目标 locale 从全局 App 词典解析。

- 自动测试验证 locale 解析、模板隔离、英文生成内容和工作区调用契约；App 内真实语言切换、
  模板编辑和下载体验仍应在 Android 与 Windows 实机界面进行人工确认。

  会明确说明并链接这些中文权威资料。
- 新增全局启用 locale 时，缺少任一提示词模板、全局动态文案键或 Flutter 资产目录都会由
  契约检查或运行时清单校验直接拒绝，不会静默回退为不完整语言。

## 升级、回滚与数据清理

- 从 4.0.0 升级不需要迁移游戏包、SDK、用户数据、Catalog 数据或 Relay 配置。
- 既有默认语言自定义提示词路径继续读取；英文和以后新增语言的覆盖写入各自 locale 子目录。
- 回滚到 4.0.0 时，新 locale 覆盖文件不会被旧版读取，但不会破坏默认语言覆盖或游戏数据；
  重新升级后可继续使用。
- 不需要执行数据清理。若只想恢复某个语言模板，必须在该 locale 下调用对应 reset 接口，
  不要删除其他语言目录。
