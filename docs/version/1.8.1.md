## 用户功能变化

- 历史游戏缺少 `author` 时显示“佚名”，缺少 `lastModifiedAt` 时显示“无”。
- 只要 `main.json` 能解析出非空 `id`，其他字段、能力或入口损坏都不会再阻断 App 和开发者工作区；条目显示为“待修复”且在修复前不能运行。
- 新增仅存本机的最近打开时间。游戏库默认按最近打开时间倒序，未打开游戏置后；删除游戏同步删除该记录。
- 详情页紧凑展示作者、最后上传、最近打开和清单状态。

## 开发与恢复

- Developer Gateway 的项目包 GET 和 `playmesh-cli get` 不执行 Manifest、能力、入口或运行校验，缺少 `app/` 时仍下载现有文件，避免损坏项目无法自救。
- 结构化 Manifest 保存、`push/dev`、运行和正式导入继续严格校验。
- 最近打开映射存于 `playmesh-library/cache/app/game-library.json`，不写入游戏 `main.json`，不进入导入、导出、开发历史或网页资源映射。每个游戏 ID 只保留一个覆盖式 Unix 毫秒值，删除游戏时同步清除，最多保留 2048 条并淘汰最旧记录。
- App 分享、在线库和 Developer Gateway 分别复用固定名称的临时 ZIP；操作前删除遗留同名文件，完成后清理，共享同一中转文件的入口串行执行。

## 兼容性

- `author` 与 `lastModifiedAt` 在当前发布链路中仍由平台注入且只读，但解析旧包时改为可缺省。
- 安全边界未放宽：宽松模式只用于发现、列表和拉取；路径越界、文件大小、正式导入、发布和运行仍使用原校验。
- 固定临时文件可能在异常退出后残留一个文件，但下一次同类操作会先删除或覆盖，不会按操作次数持续增长。
