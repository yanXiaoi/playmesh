## 用户功能

- 游戏库可以导入没有 `main.json` 的普通网页 ZIP。包内存在 HTML 时，App 会让用户
  确认游戏名称、主屏方向、游戏模式、显示模式和主入口；单屏多人另外选择控制器方向
  与控制器入口。找到 `index.html` 时优先使用其非空 `<title>` 作为默认名称。
- 普通网页包会转换为标准 `main.json + app/` 结构。转换只适配目录、根资源路径和
  主屏/控制器入口，不会自动增加游戏状态同步或联机玩法；没有 HTML 的压缩包会明确
  拒绝，已有根 `main.json` 的包继续执行严格标准包导入。
- 为兼容 Cocos HTML 游戏较大的 `.wasm`、`.data` 和资源合包，游戏包导入预算提高为
  压缩文件 100 MiB、解压总量 512 MiB、单文件 128 MiB、最多 8000 个文件。
- Go Server 在接收游戏包时持久化规范化 ZIP 的实际字节数，并通过 Catalog 列表返回；
  下载弹框会在 App 分发源临时压缩时显示准备状态，传输开始后展示总大小、当前速率和
  已下载/总量，完成传输后明确进入校验安装阶段。
- 支持 ARCore 的 Android 终端新增 `sensor.pose6d@1.0.0`。游戏可以只消费轻量
  位姿，不需要渲染相机画面。
- 位姿以米为位置单位，返回 `[x, y, z]` 与 XYZW 顺序四元数；跟踪状态为
  `tracking`、`paused` 或 `stopped`。
- 每个能力实例拥有独立游戏原点，可调用 `recenter()` 重新定位。多个实例共享一个
  ARCore Session，最高请求频率决定原生采样频率。
- 网页只有在确实需要画面时才调用 `openVideo()` 和
  `playmesh.app.media.open()`；关闭媒体会话后继续保留轻量位姿能力。

## SDK 与媒体架构

- `playmesh.app.media.open(source, {signal})` 接受能力签发的不透明实时媒体源并返回
  `{id, source, stream, state, close()}`。当前返回标准 `MediaStream`。
- 公共 Dart 媒体运行时通过 `AppMediaAdapter` 注册具体协议，按可用性、生产者和优先级
  选择适配器，再统一管理公共源 ID、会话 ID、来源校验和释放。
- `AppMediaSourceRequest.sourceOptions` 只描述视频尺寸、帧率等源需求；
  `adapterOptions` 是独立不透明对象，公共层不解析，只有被选中的适配器可以定义和
  校验内容。
- WebRTC 是首个适配器而不是公共媒体协议。网页侧 SDP offer 位于
  `adapterOptions.offer`，Android WebRTC 适配器自行解析并返回 answer；公共媒体层
  不包含 SDP、ICE、PeerConnection 或 WebRTC 条件分支。
- offer/answer 通过既有 App Bridge 完成一次交换，连接只存在于同一终端的 WebView
  与原生宿主之间。当前实现不开放 URL、端口或跨设备媒体入口，也不需要额外信令
  服务器、STUN 或 TURN。
- 新增其他协议时，实现并注册新的 Dart `AppMediaAdapter` 与对应网页适配片段即可；
  能力插件、公共运行时和 `playmesh.app.media.open()` 不需要修改。

## `sensor.pose6d` 契约

```js
const pose = await playmesh.app.capabilities.create("sensor.pose6d", {
  rateHz: 30,
});

pose.addEventListener("pose", (frame) => {
  updatePose(frame.position, frame.rotation);
});

await pose.invoke("recenter");

const source = await pose.invoke("openVideo", {
  width: 1280,
  height: 720,
  fps: 30,
});
const media = await playmesh.app.media.open(source);
video.srcObject = media.stream;

await media.close();
await pose.dispose();
```

- `rateHz` 必须是 `1..60` 的整数，缺省为 `30`。
- `openVideo` 的 `width`、`height`、`fps` 是请求偏好；`createVideoSource` 是同契约
  的描述性别名。相机实际分辨率仍由
  ARCore/设备决定。
- `captureTimestampNs` 使用字符串承载原生纳秒时间戳，避免 JavaScript Number 丢失
  64 位整数精度。
- `addEventListener/removeEventListener` 是兼容新增；既有 `on()` 返回取消订阅函数的
  形式继续可用。

## 权限、安全与生命周期

- 游戏必须在当前页面角色的 `capabilities.json` 中声明 `sensor.pose6d`，并通过每次
  加载的能力确认。
- 创建实例时才申请 Android 相机运行时权限；用户拒绝、设备不支持 ARCore 或
  Google Play Services for AR 未就绪时明确失败，不返回伪造位姿。
- App bootstrap 不探测 ARCore、硬件或系统服务，能力注册表也没有异步预探测阶段；
  只有网页实际创建 `sensor.pose6d` 时才启动原生创建，失败直接返回。
- 开发者一键自检与游戏共用真实创建路径：调用 `create({})`，成功后立即
  `dispose()`；创建或释放失败即报告自检失败。
- ARCore Session 在最后一个实例释放、页面重载、游戏退出、Bridge reset 或 Activity
  销毁时停止。Activity 进入后台时暂停，回到前台后恢复。
- 媒体源绑定签发它的页面运行时；网页篡改描述符、使用已释放源或跨页面复用都会被
  拒绝。释放源前先关闭其全部消费者。
- 位姿和视频不经 Authority Session、分享网关或局域网广播，不会自动发送给其他玩家。

## WebView 权限兼容修复

- 摄像头、麦克风和 MIDI SysEx 权限由统一能力注册表按当前页面角色声明、插件可用性
  和唯一平台授权执行器处理。
- 能力描述符以 `CapabilityPlatform.WINDOWS/ANDROID/HTML` 枚举列表
  `supportedPlatforms` 作为唯一平台声明；注册表先按当前平台列表门控，再查询驱动或
  硬件可用性。项目创建/修改弹窗只显示列表中实际支持的平台。
- 旧的 `appSupported/htmlSupported` 元数据不再生成。游戏包仍只保存能力 code，
  `playmesh.app.platform` 等现有平台协议值也没有变化。
- 本地游戏页与远程加入页使用同一检查链；新导航会清除旧页面声明和确认状态。
- Android 加入页补齐网页文件选择器，但仍只响应用户主动触发的
  `<input type="file">`，不申请存储权限。

## 兼容性

- Game SDK 与 App Bridge SDK 均为向后兼容的 MINOR 升级；注册表仍接受此前已注册
  版本范围。
- `CapabilityHandle.on()`、`onError()`、`invoke()` 和 `dispose()` 没有变化。
- 既有摄像头 `getUserMedia()`、麦克风、MIDI 与震动能力继续使用原调用方式。
- 游戏包的 `capabilities.json` 仍只保存能力 code，不需要迁移。
- Developer API 的能力描述符响应删除旧双布尔字段，因此契约升级到 `3.0.0`；Operation
  路径和请求结构不变。随 App 分发的 Developer CLI 已升级到 `1.5.0` 并适配新列表。
- 没有新增 Go Core、Relay、Catalog 或数据迁移要求。

## 已知限制与人工验收

- `sensor.pose6d` 当前只在 Android ARCore 终端可用；iOS、Windows 和普通浏览器会
  报告不可用。
- 当前视频适配器面向同一终端内的原生宿主到 WebView，不是跨设备视频服务；如果未来
  新增跨设备媒体，必须单独设计鉴权、信令、网络暴露与隐私边界。
- ARCore 可能要求用户安装或更新 Google Play Services for AR；完成后需要重新创建
  能力实例。

## 升级与回滚

- 无数据库、游戏包或 Go Core 迁移。
- 可直接覆盖安装 `3.1.0+24`。
- 回滚到 `3.1.0+24` 不需要清理数据，但 `sensor.pose6d` 与
  `playmesh.app.media` 将不可用，声明这些能力的游戏必须提供降级路径。
