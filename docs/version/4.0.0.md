## 破坏性边界

本版本不提供迁移适配器、旧路由别名、旧 SDK 根成员或旧 CLI 命令：

- 游戏包继续使用物理根 `main.json`、可选 `capabilities.json`、可选安全根
  `icon.png` 与必需 `app/`，外层物理 `app/` 直接映射为运行时 `/`。用户首段
  `app` 合法：物理 `app/app/**` 映射为 `/app/**`，Manifest 入口
  `app/index.html` 解析到物理 `app/app/index.html`；它不会别名到外层
  `app/index.html`。
- `/playmesh/**` 与 `/bucket/**` 仍是仅有的平台保留顶层。物理 `app/` 禁止一级
  `playmesh/`、`bucket/` 及其大小写、编码、反斜杠、空段和穿越绕过。
- `entries.game`、`entries.controller` 与 `authority.entry` 全部相对于外层物理
  `app/`；页面入口只允许 `.html`，Authority 入口只允许 `.js` 或 `.mjs`。`app`
  可以作为普通首段，只有 `playmesh`、`bucket` 是保留首段。所有运行、分享和邀请
  链路使用清单实际声明，不硬编码默认页面。
- `entries.game` 对所有游戏显式必填；`single_screen_multiplayer` 必须显式声明
  `entries.controller`；`multiplayer` 必须显式声明 `authority.entry`。缺失字段
  直接拒绝，模板仍生成 `index.html`、`controller/index.html` 与
  `static/js/service/index.js` 的实际声明。
- 旧 CLI 1.x 项目布局、`create/push/sdk` 命令和明文目标凭据不再识别，也不执行隐式
  迁移。旧 JavaScript 发布包只能在空目录通过 `get` 恢复为 JavaScript 2.0 工程；
  TypeScript 类型结构与 Cocos 场景工程必须从原始源码恢复。

## SDK 4.0 命名空间与文件

主 SDK 与 App SDK 必须成对注入：

```text
/playmesh/sdk/v1/playmesh-main.js
/playmesh/sdk/v1/playmesh-app.js
```

类型文件固定为 `playmesh-main.d.ts` 与 `playmesh-app.d.ts`。旧 `playmesh.js`
与旧 Game 类型文件均不兼容、不回退。

- 游戏本体、声明、会话、玩家、Authority、消息、同步、Binary、生命周期与存储只位于
  `playmesh.main.*`。
- 当前客户端的身份、locale、性能、平台能力、媒体、设备、UI 与日志只位于
  `playmesh.app.*`。
- 面向游戏开发者的唯一全局对象是 `window.playmesh`，其根级公开成员严格只有
  `ready`、`main` 与 `app`。`window.playmeshApp` 不存在，公开的 `main`/`app`
  不包含任何 `__*` 内部桥接；两个 SDK 的内部协作改为不可枚举的私有 `Symbol`
  runtime，且不进入声明、Manifest、提示词、补全或游戏可调用 API。
- locale 固定为 `playmesh.app.runtime.getLocale()`。
- FPS 与延迟固定为 `playmesh.app.performance.*`；
  `playmesh.main.performance` 不存在。
- 性能浮层唯一由 App SDK 创建和维护；Game SDK 的旧浏览器性能 panel 已删除。
- `playmesh.main.ready` 内部先等待 `playmesh.app.ready`；根 `playmesh.ready`
  只复用这条初始化链并返回 `{main, app}`；旧 `playmesh.session`、
  `playmesh.game`、`playmesh.storage` 等路径均无效。

SDK 的 TypeScript 片段、声明、Dart 宿主执行器、精确发行版本、Manifest、Schema、模板、
编辑器补全、AI 提示词和运行时响应继续由同一 Dart Feature 注册表生成。

清单版本采用严格匹配：`main.json.sdkVersion` 必须为 `4.0.0`，
`main.json.appSdkVersion` 必须为 `3.2.0`。任何旧值、未知值或格式错误值都直接拒绝；
本版本不提供旧清单版本解析、版本回退或旧命名空间 shim。

## 外部工程与 Developer CLI 2.0

所有外部工程使用唯一 `adapter.Registry` 接入 JavaScript、TypeScript 与
Cocos Creator 3.x，未来 Godot 等引擎也只能在 CLI 组合根注册 `Adapter`。项目结构
固定为：

```text
playmesh-cli.json
playmesh/
  package/
    main.json
    capabilities.json  # 可选
    icon.png            # 可选安全根图标
    app/
  sdk/
    playmesh-main.js
    playmesh-app.js
    playmesh-main.d.ts
    playmesh-app.d.ts
```

只有 `playmesh/package/` 中的必需 `main.json`、可选 `capabilities.json`、可选安全根
`icon.png` 与必需 `app/` 进入完整上传；`playmesh/sdk/` 永不上传。
上传校验不会把用户首段 `app` 当作旧协议特殊处理：清单 `app/index.html` 与物理
`playmesh/package/app/app/index.html` 是合法对应关系。

- `init` 创建 JavaScript/TypeScript 项目，`init cocos` 安装 Cocos Creator 3.x
  项目级扩展。
- `dev` 通过受控本地代理在真实 App WebView 中运行并跟随日志。仅目标缺少项目时上传
  最小基础包，普通网页资源变化不触发完整上传。
- `run` 执行适配器正式构建、完整上传、原子安装和启动，输出 `runId` 后返回，不附加
  日志。
- `logs` 只读并跟随当前项目运行日志；`update` 更新 SDK 后刷新对应适配器；`get`
  只允许空目录并固定生成 JavaScript 2.0 工程。
- Windows 目标 token 使用当前用户 DPAPI，macOS 使用 Keychain，Linux 使用 Secret
  Service；旧明文配置拒绝读取并要求重新执行 `to`。
- Cocos Web Mobile/Web Desktop 构建结果原子写入 `playmesh/package/app/`。预览地址
  按显式扩展消息、`PLAYMESH_DEV_SERVER_URL`、
  `integration.developmentServerUrl` 依次解析。
- 开发资源统一实现 `development.Source` / `development.Mapping`：
  Adapter 只提供固定来源、路径、headers 与 `Start/Stop` 生命周期。CLI 公共代理和
  App Developer Gateway 都不读取 Adapter/引擎类型；不维护第二份 Adapter 实例表，
  新增 Godot 等引擎时只增加 CLI Adapter 实现及其唯一注册项，不修改 App 代码或
  App 资源源类型，也不为 Cocos 或未来引擎新增第三套代理。

## Developer API 4.0 与开发资源

Developer API 新增
`GET/POST/DELETE /dev/api/projects/{projectId}/development`。开发会话绑定当前项目、
CLI 来源、一次性资源凭据、固定 HTTP 根地址和最长 24 小时有效期，只驻留内存且绝不
回传凭据。

App 只区分正式已安装游戏资源和临时开发资源，二者共用
`GameWebResourceSource` / `GameWebResourceProvider` 接口。开发态仅把普通 GET、
HEAD 与 WebSocket 请求转发到固定上游，`/playmesh/**`、`/bucket/**` 继续由 App
本地处理。重复 `dev`、正式
`run/restart`、DELETE、到期和 Gateway 关闭均按 `runId` 串行：新运行开始前关闭旧
页面、HTTP 资源、上下游 WebSocket 和凭据；停止失败保留可重试状态。
App 只接收 CLI 公共代理给出的 `resourceBaseUrl + credential + expiresAt`，不会看到
或判断 JavaScript、TypeScript、Cocos、Godot 等项目类型。
在开发资源链路中，Developer Gateway 位于控制面，负责建立和撤销开发会话；页面资源
请求仍经 `GameAssetGateway` 与开发 Provider 转发。主机/加入端、浏览器/App、局域网/
公共中转是正交的共享与传输维度，不改变正式已安装或临时开发资源的选择。

游戏启动全屏由启动入口显式传递。游戏库详情与首页快速游戏固定全屏；开发者工作区、
CLI `run` 与 CLI `dev` 在 Android/iOS 手持端保持全屏和方向锁定，在 Windows、
macOS 与 Linux 桌面端默认窗口化。控制器/加入端继续默认全屏；此策略不限制 SDK
运行中主动切换全屏，窗口化开发页退出时会清理 SDK 临时进入的全屏状态。

## 游戏包导入、Catalog 与 Relay

- 游戏库继续严格导入带根 `main.json` 的标准包；无 `main.json` 但包含 HTML 的普通
  网页 ZIP 可由用户确认名称、方向、模式、显示方式和入口后转换为标准包。转换剥离
  统一公共外层目录并迁入物理 `app/`，保留原相对路径、根路径、外部 URL、未知路由与
  二进制内容；转换器不会为外层目录自动增加 `/app` 前缀，但用户原有的 `app/`
  目录与 `/app/**` 引用保持不变。
- Catalog API `3.0.0` 与 App 使用同一根相对入口、扩展名、保留目录和安全 ZIP 校验。
  包列表可返回 `packageSizeBytes`，下载包与上传包均保留可选根 `icon.png`。
- Relay `3.0.0` 的局域网与端点加密邀请保存清单实际根相对入口，不接受 Relay 2.x
  邀请；`app/...` 入口按原值生成 `/app/...`，并解析到物理 `app/app/...`，不提供
  指向外层 `app/...` 的回退别名。

## 升级与回滚

这是破坏性更新，不保留 3.x SDK 根成员、旧 `playmesh.js`、把外层物理
`app/` 自动别名为 `/app/**` 的行为、CLI 1.x 布局、旧命令或明文凭据迁移。用户
实际创建的物理 `app/app/**` 仍按普通路径映射为 `/app/**`。需要保留
TypeScript/Cocos 源码时必须使用版本库；App 已发布 JavaScript 包只能通过 CLI 2.0
`get` 恢复为新的 JavaScript 工程。
