# Playmesh extensions

Playmesh-owned GDevelop extension JSON files and their `index.json` live in
this directory. They are public Library resources, not official GDevelop
catalog artifacts, and must not be copied into the upstream source tree, the
generated official catalog, or the WebIDE ZIP.

The Developer Gateway exposes this directory at
`/playmesh/GDevelop/playmesh/extensions/`. The WebIDE loads `index.json` from
that same-origin route and then loads every listed JSON body. Adding another
local extension therefore requires only its JSON file plus one index entry;
it does not require a new WebIDE package.

Index paths are single safe `.json` filenames. Paths and resolved extension
names must be unique, and an optional index `name` must match the body `name`.
The layout and runtime loaders reject traversal, nested paths, duplicate
entries, oversized files, malformed JSON, and partial local catalogs.

The official GDevelop Multiplayer compatibility layer remains a source
overlay so projects keep the official
`Multiplayer::MultiplayerObjectBehavior` JSON and remain portable to official
GDevelop.

## Playmesh SDK extension

`Playmesh.json` is generated by
`../scripts/generate-playmesh-extension.mjs`; do not edit the JSON body by
hand. The public editor surface is split into `Main SDK（游戏 SDK）` and
`App SDK（原生 SDK）`, then grouped by SDK semantics. SDK readiness is injected
by the host, so the extension does not expose a second ready action or load a
second SDK copy.

Browser multiplayer previews and exported games use that same SDK identity flow:
when no valid nickname is stored, it saves `浏览器` followed by four random
lowercase letters or digits without opening a setup dialog. Existing nicknames
and manual renaming in game information remain available; the extension does
not generate or store a separate nickname.

The generator embeds the current 256×256 public Playmesh brand derivative at
`../../../developer/playmesh-logo.png` into both `iconUrl` and
`previewIconUrl`. Regenerate the extension after the shared brand assets are
updated; the generator rejects an unexpected image format or size.

The normal editor actions use fixed SDK members and typed parameters. Known
App capabilities are generated from the default Dart capability descriptors,
with a snapshot parity test keeping their codes, methods, events, schemas and
platform declarations aligned. `设备环境` is the `playmesh.app.device` API;
camera, microphone, MIDI, vibration and pose are separate capability groups.
The open registry entry points remain under `动态能力（高级）` for future
capabilities that are not present when this extension is generated.

GDevelop variables are used only where the SDK contract itself accepts or
returns open JSON, arrays, or structured records. Binary data, files, media
streams, channels, controllers, buckets, capability instances and LAN results
use explicit encoding helpers or opaque handle IDs. Meaningful optional SDK
arguments always have a separate `Use...` switch because GDevelop's optional
parameters do not preserve JavaScript `undefined`.

Regenerate and verify the extension with:

```powershell
node ..\scripts\generate-playmesh-extension.mjs
node ..\scripts\generate-playmesh-extension.mjs --check
```
