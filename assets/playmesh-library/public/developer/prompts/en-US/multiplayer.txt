[Current mode rules: shared multiplayer rules]
This is a multiplayer game. `playmesh.main.sync` runs internal game rules on the Authority page and maintains one public JSON state shared by all session participants. Players submit game intent through sync input. Authority may use `onInput` to process each `submitAction` and transmitted `submitState` input, and provides `onTick` when rules need fixed-rate progression. `submitState` rate-limits and coalesces continuous input by player and key. After the initial snapshot, automatic complete public snapshots are change-driven, capped at `tickRate` sends per second, coalesced within each window, deduplicated by final state, and sent serially. Player-specific JSON uses `playmesh.main.game.submitAction`, targeted `playmesh.main.authority.onService` results, and `playmesh.main.game.onMessage` on recipients. Go Core routes the protocol. Non-Authority multiplayer pages automatically request the latest public snapshot when ready.
The platform transparently handles transport differences between join methods. Game code always uses the same Game SDK; never detect the transport, read share parameters, or branch the session protocol by join method.

Required deliverables:
1. `main.json` must explicitly declare `authority.entry`. The referenced file must exist and export working Authority state rules; never omit it or rely on a default entry.
2. The Authority page must load that service and call `playmesh.main.sync.startAuthority` only when `playmesh.main.session.isAuthority()` is true.
3. Define an `onInput` rule for every business-input structure submitted through `playmesh.main.sync.submitAction`. Submit continuous input through `submitState` and process it in `onInput` or `onTick` inputs.
4. Every page must present the latest snapshot through `playmesh.main.sync.observe`; local prediction is never the final result.
5. Identity comes only from `context.senderPlayerId` and `context.members[].id`; `player.playerId` and `member.playerId` do not exist.
6. Use `playmesh.main.storage` for persistent information such as saves, long-term progress, and game settings. Use sync state for the current round's public state.
7. Authority maintains readiness, waiting, countdown, and start conditions according to the current game's rules. When the game has a ready flow, present its waiting state through public sync state.
8. The App host that creates and runs the session is always Authority. Never infer Authority from `session.players[0]`, player-array order, the first input sender, or "the first player". Pages use only `playmesh.main.session.isAuthority()`; authoritative rules use only `session.authorityClientId` to verify Authority identity.

SDK:
- `playmesh.main.session.getCurrent()`: current `SessionSnapshot`, or null.
- `playmesh.main.session.onStateChange(callback)`: receives the current session snapshot immediately and future snapshots; returns an unsubscribe function.
- `playmesh.main.session.onPlayerJoin(callback)`, `onPlayerLeave(callback)`, and `onPlayerReconnect(callback)`: handle first join, disconnect, and reconnection with the same ID; each returns an unsubscribe function. Never use nickname or position in `players` to identify the same player.
- `playmesh.main.session.isAuthority()`: whether this page belongs to the App Authority Client that created and runs the session. Player join order never changes the result.
- `playmesh.main.session.start()`: Authority only. Requests that Core move a session satisfying the base player-count constraint to `running`. The SDK does not determine readiness, countdown, or game-specific start conditions; implement those states with sync input and authoritative game state.
- `playmesh.main.session.finish()`: Authority only. Call only after game rules confirm the round has truly ended. Requests that Core move the session to `stopped` and clear disconnected members. The SDK does not decide victory or end conditions; page visibility, a temporary disconnect, or pause is not game completion.
- `playmesh.main.player.getCurrent()`: current Player; may be null on a public display.
- `playmesh.main.player.setNickname(name)`: available on multiplayer Player pages in ordinary browsers and App WebViews. A browser writes the nickname preference to localStorage for the current origin; the App host persists it, and both synchronize the current Core. It is unavailable in solo mode and on the `single_screen_multiplayer` public Authority display. Never rewrite browser storage, the App profile, or Core player state directly.
- `playmesh.main.sync.startAuthority(options)`: available to Authority. `initialState` is required and becomes the public initial state. `stateType` is optional. `tickRate` defaults to 10, accepts integers from 1 through 60, sets the per-second limit for automatic complete snapshot sends, and sets the maximum `onTick` rate when `onTick` is provided. `onInput` and `onTick` are optional.
- `controller.getState()`: returns a JSON copy of the current Authority runtime public state.
- `controller.setState(nextState, publish?)`: replaces the complete current public state. Real changes enter automatic publication. `publish` defaults to true so the Promise waits for the associated flow to settle with a snapshot or null and rejects on send failure. False resolves immediately with null, while later automatic publication may still synchronize the changed state.
- `controller.publish(targetPlayerIds?)`: each call independently constructs a complete snapshot of the current public state at call time and starts sending it immediately. Explicit publication uses an independent concurrent path, and the game controls its call rate. `targetPlayerIds` selects recipients for that snapshot; omitting it selects the Authority Client and Session players.
- `controller.publish(state, targetPlayerIds?)`: in one call, replaces the complete public state so `getState()` can read it immediately, then constructs and starts sending a snapshot of that same state. When state is a string array, pass the second argument explicitly (it may be undefined) to select this overload.
- `controller.stop()`: stops this page's tick and synchronization runtime and cancels automatic publication tasks that have not started. Sends already started continue to settle. Start later synchronization with `startAuthority`; manage the Session lifecycle independently.
- Automatic publication: when `onTick` is provided, each tick schedules at most one automatic snapshot. When `onTick` is omitted, the first change opens one one-shot send window and later changes in that window update only the final state. A later final state formed during an automatic send enters the next window. Automatic sending proceeds when the final state differs from the last public publication. Each automatic snapshot is processed by the same serialized rate-limited queue.
- `onInput(input, context)`: runs for each received `submitAction` or transmitted `submitState` input. It may synchronously or asynchronously return the next complete public state; `undefined` preserves the current state. `context` contains `senderPlayerId`, `state`, `inputId`, `inputType`, `key`, `receivedAt`, `session`, and `members`.
- `onTick(context)`: runs only when provided, up to `tickRate` times per second, with non-overlapping callbacks. It may synchronously or asynchronously return the next complete public state; `undefined` preserves the current state. `context` contains `state`, `inputs`, `tick`, `dt`, `now`, `session`, and `members`. Read continuous input values from `inputs[playerId][key].value`.
- `playmesh.main.sync.submitAction(input)`: submits a one-shot JSON game intent; the Promise resolves to an `inputId`.
- `playmesh.main.sync.submitState(key, value, {rateHz})`: `key` must match `^[A-Za-z0-9._-]{1,64}$`; `rateHz` defaults to 20 and must be from 1 through 60. Each key is throttled and only its latest value is retained. The Promise resolves when the input enters the local send queue; subsequent Authority snapshots or targeted messages carry the remote processing result.
- `playmesh.main.sync.observe(callback)`, `getSnapshot()`, and `requestSnapshot()`: read or request a complete, revisioned authoritative snapshot. Only non-Authority multiplayer pages call `requestSnapshot` automatically when ready.
- Player-specific JSON channel: players use `playmesh.main.game.submitAction(action)`, Authority returns targeted messages with `targetPlayerIds` from `playmesh.main.authority.onService(handler)`, and recipients subscribe through `playmesh.main.game.onMessage(callback)`. `onEvent(callback)` is the compatibility alias of `onMessage`.
- The Authority handler receives `(action, {senderPlayerId, session, members})` and may return `{targetPlayerIds, message}`, an array of results, null, or a Promise. Targets normally use `members[].id`. To include the public display, add `session.authorityClientId` and deduplicate.

Key types:
`Player = { id, nickname, role: "authority" | "authority_player" | "player", connected }`
`SessionSnapshot = { id, joinCode, gameId, displayMode: "multi_screen" | "single_screen_multiplayer", state: "lobby" | "running" | "paused" | "stopped", minPlayers, maxPlayers, authorityClientId, players }`
`SyncSnapshot = { protocolVersion, stateType, full, revision, sequence, timestamp, sourceTick, state }`

Minimal Authority structure:

export function startAuthoritySync() {
  return playmesh.main.sync.startAuthority({
    initialState: { value: 0, updatedBy: null },
    tickRate: 10,
    onInput(input, context) {
      if (input?.type !== "state.increment") return context.state;
      return { value: context.state.value + 1, updatedBy: context.senderPlayerId };
    },
  });
}

The browser SDK persists a random player ID and nickname in localStorage for the current origin. App players use their automatically injected ID and nickname. Game code must not manually set, rewrite, or carry player IDs in URLs. Only one online connection may use a player ID at a time; reconnection with the same ID is allowed only after the previous connection closes.

Core retains disconnected members only while a session is `running` or `paused`, enabling mid-game join, waiting, and reconnection. A disconnect in `lobby` releases the member immediately; `stopped` retains no disconnected members. Update waiting/reconnection UI from connection events and restore gameplay from authoritative snapshots.

Never trust a player ID, role, score, answer, winner, or final result claimed by input. Only Authority may change multiplayer state, and Player pages use the latest Authority snapshot as the final result.
