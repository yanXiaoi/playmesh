[Current display type: single-screen multiplayer]
`main.json` must declare the main-screen `orientation` and controller `controllerOrientation` separately. On entering fullscreen, the SDK/host requests the orientation for the current page role. Pages must still use responsive layouts in case the browser refuses orientation locking.
`capabilities.json.required` applies only to the `entries.game` main screen, while `controllerRequired` applies only to the `entries.controller` controller. An empty array means that endpoint declares no capabilities; never fall back to or merge the other endpoint's declarations. Neither endpoint may use capabilities declared only for the other role.
The host loads the explicitly declared and existing `main.json.entries.game` as the public display and Authority Client. Every player loads the explicitly declared and existing `entries.controller`. Neither entry may be omitted or use a default. The public display is not in `session.players`; treat `playmesh.main.player.getCurrent()` as null.

Required deliverables:
- `entries.game`: public display, session presentation, Authority registration, and authoritative state presentation only; it provides no player input.
- `entries.controller`: player input, business-intent submission through `submitAction` or `submitState`, and public synchronized snapshot consumption.
- Authority service: processes controller input through `playmesh.main.sync` and updates authoritative state; the SDK automatically distributes snapshots to the public display and players.

Strictly prohibited:
- The controller page must not import or register the Authority service.
- The public display must not assume `player` is non-null or add the host to `players`.
- Do not generate the standard multiscreen flow where every device runs the same game entry.
- Do not generate a solo-only flow.

Minimal public-display structure:

import { startAuthoritySync } from "../service/index.js";
await playmesh.ready;

function showError(error) {
  const message = error instanceof Error ? error.message : String(error);
  const target = document.querySelector("#error");
  if (target) target.textContent = message;
  console.error(error);
}

try {
  if (playmesh.main.session.isAuthority()) {
    startAuthoritySync();
  }
} catch (error) {
  showError(error);
}
playmesh.main.session.onStateChange(renderSession);
playmesh.main.sync.observe((snapshot) => render(snapshot.state));

Minimal controller structure:

await playmesh.ready;
function showError(error) {
  const message = error instanceof Error ? error.message : String(error);
  const target = document.querySelector("#error");
  if (target) target.textContent = message;
  console.error(error);
}
document.querySelector("#action").addEventListener("click", async () => {
  try {
    await playmesh.main.sync.submitAction({ type: "state.increment" });
  } catch (error) {
    showError(error);
  }
});
playmesh.main.sync.observe((snapshot) => render(snapshot.state));

Single-screen multiplayer places player interaction in `entries.controller`, while the public display presents the session and public state. Controllers submit one-shot intents such as readiness through `submitAction`, and Authority handles them with `onInput`. Games that advance a countdown or real-time rules by time also provide `onTick`. After the current game's start conditions are satisfied, Authority calls `playmesh.main.session.start()` and handles the result or error.
