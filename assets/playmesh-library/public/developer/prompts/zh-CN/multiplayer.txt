【当前模式规则：联机游戏公共规则】
这是联机游戏。playmesh.main.sync 在 Authority 页面执行游戏内部规则，并维护一份所有会话参与端共享的公共 JSON 状态。玩家通过 sync 输入提交业务意图；Authority 可使用 onInput 逐次处理 submitAction 和实际发出的 submitState 输入，并在规则需要按固定频率推进时配置 onTick。submitState 按玩家和 key 限频、合并连续输入。初始快照之后，自动完整公共快照按状态变化触发，以 tickRate 为每秒发送上限，合并窗口内变化、去重最终状态并串行发送。玩家专属 JSON 信息通过 playmesh.main.game.submitAction 交给 playmesh.main.authority.onService，由 Authority 使用 targetPlayerIds 定向返回，并在接收端通过 playmesh.main.game.onMessage 处理。Go Core 负责协议路由。非 Authority 多人页面就绪时会自动请求最新公共快照。
不同加入方式的底层传输由平台透明处理；游戏代码始终使用同一套 Game SDK，不得探测传输实现、读取分享参数或按加入方式分叉会话协议。

强制交付：
1. `main.json` 必须显式声明 `authority.entry`；它指向的文件必须真实存在，并导出可工作的 Authority 状态规则，不得省略或依赖默认入口。
2. Authority 页面必须加载该 service，并且只在 playmesh.main.session.isAuthority() 为 true 时调用 playmesh.main.sync.startAuthority。
3. 通过 playmesh.main.sync.submitAction 提交的每种业务输入结构，都在 onInput 中定义对应处理规则；连续输入通过 submitState 提交，并可在 onInput 或 onTick 的 inputs 中处理。
4. 所有页面必须使用 playmesh.main.sync.observe 展示最新快照，不能把本地预测当作最终结果。
5. 身份只能使用 context.senderPlayerId 和 context.members[].id；不存在 player.playerId 或 member.playerId。
6. 存档、长期进度和游戏配置等持久信息使用 playmesh.main.storage；当前局公共状态使用 sync state。
7. 准备、等待、倒计时和开局条件由 Authority 按当前游戏规则维护；需要准备流程时，通过公共 sync state 展示等待状态。
8. Authority 固定为创建并运行当前会话的 App 主机端。不得通过 session.players[0]、玩家数组顺序、首个输入发送者或“第一个玩家”推断 Authority；页面只使用 playmesh.main.session.isAuthority()，权威规则只使用 session.authorityClientId 校验 Authority 身份。

SDK：
- playmesh.main.session.getCurrent(): 当前 SessionSnapshot 或 null。
- playmesh.main.session.onStateChange(callback): 立即及后续接收会话快照，返回取消订阅函数。
- playmesh.main.session.onPlayerJoin(callback)、onPlayerLeave(callback)、onPlayerReconnect(callback): 分别处理首次加入、掉线和同 ID 重连，均返回取消订阅函数。不要用昵称或 players 数组位置判断同一玩家。
- playmesh.main.session.isAuthority(): 当前页面是否为创建并运行会话的 App Authority Client；玩家加入顺序不会改变结果。
- playmesh.main.session.start(): 仅 Authority 请求 Core 把满足基础人数条件的会话切换为 running。SDK 不判断准备、倒计时或玩法开始条件；这些业务状态由游戏通过 sync 输入和 Authority 权威状态实现。
- playmesh.main.session.finish(): 仅 Authority 在游戏规则已确认本局真正结束后，请求 Core 切换为 stopped 并清理本局离线成员。SDK 不判断胜负或结束条件；不要把页面隐藏、临时断线或暂停当作游戏结束。
- playmesh.main.player.getCurrent(): 当前 Player；公共显示端可能为 null。
- playmesh.main.player.setNickname(name): 多人 Player 页面在普通浏览器和 App WebView 中可用。浏览器把昵称偏好写入当前 origin 的 localStorage，App 由宿主持久化，两者都同步当前 Core。单机和 single_screen_multiplayer 公共 Authority 屏不可用；游戏不得自行改写浏览器缓存、App 资料或 Core 玩家状态。
- playmesh.main.sync.startAuthority(options): 仅 Authority 可用。initialState 必填并作为公共初始状态；stateType 可选；tickRate 默认为 10，取 1 至 20 的整数，用于设置自动完整快照每秒发送上限，并在配置 onTick 时设置其最高运行频率；onInput 和 onTick 均可选。
- controller.getState(): 返回当前 Authority runtime 公共状态的 JSON 副本。
- controller.setState(nextState, publish?): 整体替换当前公共状态。真实变化进入自动发布流程；publish 默认为 true，使 Promise 等待对应流程结算为快照或 null，发送失败时 reject；传 false 时立即 resolve null，状态变化仍可由后续自动发布窗口同步。
- controller.publish(targetPlayerIds?): 每次调用都独立构造调用时的当前完整公共状态快照并立即发起发送；显式发布使用独立并发路径，发送频率由游戏调用节奏决定。targetPlayerIds 选择该快照的接收者；省略时选择 Authority Client 和 Session players。
- controller.publish(state, targetPlayerIds?): 在同一调用中整体替换公共状态，使 getState() 立即可读，再为同一状态构造快照并立即发起发送。state 为字符串数组时，显式传入第二参数（可为 undefined）以选择该重载。
- controller.stop(): 停止当前页面的 tick 与同步 runtime，并取消尚未执行的自动发布任务；已发起的发送继续结算。后续同步通过重新调用 startAuthority 启动，Session 生命周期独立管理。
- 自动发布: 配置 onTick 时，每个 tick 最多安排一个自动快照；未配置 onTick 时，首次变化开启一个一次性发送窗口，窗口内后续变化只更新最终 state。自动发送期间形成的后续最终状态进入下一窗口。最终 state 相对上次公共发布发生变化时执行自动发送；每个自动快照由同一限频串行队列处理。
- onInput(input, context): 每次收到 submitAction 或实际发出的 submitState 输入时运行，可同步或异步返回下一份完整公共状态；返回 undefined 时保持当前状态。context 包含 senderPlayerId、state、inputId、inputType、key、receivedAt、session、members。
- onTick(context): 仅在配置后运行，以 tickRate 为最高频率且回调互不重叠；可同步或异步返回下一份完整公共状态，返回 undefined 时保持当前状态。context 包含 state、inputs、tick、dt、now、session、members；连续输入值读取自 inputs[playerId][key].value。
- playmesh.main.sync.submitAction(input): 提交一次性 JSON 业务意图，Promise resolve 为 inputId。
- playmesh.main.sync.submitState(key, value, {rateHz}): key 必须匹配 ^[A-Za-z0-9._-]{1,64}$；rateHz 默认为 20 且必须在 1 至 20 之间；同一 key 限频并只保留最新值。Promise 在输入进入本地发送队列时 resolve；远端处理结果通过后续 Authority 快照或定向消息体现。
- playmesh.main.sync.observe(callback)、getSnapshot()、requestSnapshot(): 读取或请求带版本的完整权威快照；只有非 Authority 多人页面会在就绪时自动 requestSnapshot。
- 玩家专属 JSON 通道：玩家使用 playmesh.main.game.submitAction(action)，Authority 使用 playmesh.main.authority.onService(handler) 返回带 targetPlayerIds 的定向 message，接收端使用 playmesh.main.game.onMessage(callback)；onEvent(callback) 是 onMessage 的兼容别名。
- authority handler 接收 (action, {senderPlayerId, session, members})，可返回 {targetPlayerIds, message}、结果数组、null 或 Promise；目标通常使用 members[].id，公共显示端需要接收时加入 session.authorityClientId 并去重。

关键类型：
Player = { id, nickname, role: "authority" | "authority_player" | "player", connected }
SessionSnapshot = { id, joinCode, gameId, displayMode: "multi_screen" | "single_screen_multiplayer", state: "lobby" | "running" | "paused" | "stopped", minPlayers, maxPlayers, authorityClientId, players }
SyncSnapshot = { protocolVersion, stateType, full, revision, sequence, timestamp, sourceTick, state }

Authority 最小结构：

export function startAuthoritySync() {
  return playmesh.main.sync.startAuthority({
    initialState: { value: 0, updatedBy: null },
    tickRate: 10,
    onInput(input, context) {
      if (input?.type !== "state.increment") return context.state;
      return { value: context.state.value + 1, updatedBy: context.senderPlayerId };
    },
  });
}

浏览器 SDK 会把随机玩家 ID 和昵称持久化到当前来源的 localStorage，App 玩家使用自动注入的自身 ID 和昵称；游戏代码不得手动设置、改写或从 URL 携带玩家 ID。同一玩家 ID 同时只能有一个在线连接，旧连接断开后才允许同 ID 重连。

Core 只在 running 或 paused 状态保留掉线成员，以便中途加入、等待与重连；lobby 掉线直接释放成员，stopped 不保留离线成员。游戏应通过连接事件更新等待/重连 UI，并通过权威快照恢复玩法状态。

不得信任 input 自报的玩家 ID、角色、分数、答案、胜负或最终结果。多人状态只能由 Authority 修改，Player 页面最终以最新 Authority 快照为准。
